# 一、Zoo Code 介绍及核心优势

## 背景由来

Zoo Code 是在原 Roo Code 基础上继续开发的产物。2026 年 5 月，Roo 团队宣布停止 Roo Code 的活跃开发，转而专注于云端代理产品 Roomote，并将 Roo Code 仓库存档在 v3.54.0。次日，由原 Roo 贡献者组成的 Zoo Code 核心团队以 Apache 2.0 许可证原样重新发布了 v3.54.0，从此持续进行模型更新、Bug 修复和功能迭代。

因此 Zoo Code 的家族谱系是：**Cline → Roo Code → Zoo Code**。它与 Cline 和 Roo Code 同源，但独立演进，被视为 Roo Code 官方推荐的社区继任者。

## 核心理念

Zoo Code 的目标是成为一个**功能完整的 AI 编程代理**，不仅限于代码补全。它能够：

- 理解整个项目的代码库结构
- 自动规划复杂的开发任务
- 执行多步骤操作（读写文件、执行命令、调用外部工具）
- 在多种工作模式间切换以适应不同场景
- 通过 Orchestrator 模式构建**多代理流水线**：父代理规划任务，将子任务委派给拥有独立上下文窗口的子代理（subagent）执行

## Zoo Code 相对 Roo Code 的新增功能

| 功能 | 说明 |
|------|------|
| **Semble 代码库智能** | 快速、按需的语义代码搜索，无需单独构建索引 |
| **增强的 Orchestrator 工作流** | 更安全的任务委派、并行任务协调、父子任务恢复 |
| **DCG 破坏性命令防护** | 自动阻止危险命令，允许可信工作继续执行，减少审批操作 |
| **最新模型支持** | 持续支持 Claude、GPT、Gemini、Kimi、GLM、Grok、MiniMax 等 |
| **更多连接方式** | Zoo Gateway、Moonshot、Kimi Code、Kenari、Friendli、OpenCode Go 等提供商 |
| **更可靠的终端和编辑工作流** | 修复终端过早完成、任务状态竞态、上下文管理等问题 |
| **更全面的工作区控制** | 规则管理、按模式限制 MCP、多根路径控制、模型推理选项 |

## 关键设计：差异编辑

Zoo Code 采用**差异编辑（diff-based editing）**：只重写文件中发生变化的行，而不是整文件重写。这既让每次代码变更清晰可审查，也显著节省了模型 Token 消耗。

## Orchestrator 多代理模式

Zoo Code 的 Orchestrator 模式源于 Roo Code 的 **Boomerang 任务**设计，把大任务拆成相互隔离的子任务：

1. **父代理**负责全局规划，把任务拆解为子任务
2. 每个子任务在**独立的上下文窗口**中运行（通常切换为其他模式，如 Code 模式）
3. 子任务完成后只向父代理返回**执行摘要**，父代理不需要看到全部实现细节
4. 子任务之间有严格的权限隔离，某一步失败可自动恢复或回滚

这种设计解决了单一上下文窗口容易占满的问题，让 Zoo Code 能在 VS Code 里编排真正意义上的"AI 开发团队"。

## 多语言支持

Zoo Code 支持 18 种语言，包括简体中文和繁体中文，中文用户可无障碍使用。

## 开源与社区

- **许可证**：Apache 2.0，完全开源、可审查、可贡献
- **社区**：Discord（实时帮助）、Reddit r/ZooCode（异步讨论）、GitHub Issues（Bug 与需求）
- **生态**：活跃的贡献者社区持续合并来自 Cline、Roo Code 等上游项目的优秀特性
