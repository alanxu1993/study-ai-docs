# 四、AI Agent 的发展历程

## 时间线总览

![幽灵沿着时间线从萌芽走向企业落地](/images/ai-agent/history/01-timeline.png)

```
1950s ──→ 1990s ──→ 2010s ──→ 2022 ──→ 2024-2026
概念萌芽    多智能体   深度学习   大爆发     企业落地
```

## 阶段一：概念萌芽期（1950s - 2010s）

### 关键里程碑

| 时期 | 事件 | 意义 |
|------|------|------|
| 1950s | 图灵测试提出 | Agent 概念初现 |
| 1966 | ELIZA 聊天机器人 | 最早的对话系统 |
| 1990s | 多智能体系统研究兴起 | Agent 协作理论建立 |
| 2000s | 规则驱动的聊天机器人 | 客服机器人应用 |

### 阶段特点

- 基于规则，能力有限
- 只能执行预定义的操作
- 缺乏真正的"智能"

## 阶段二：深度学习赋能期（2010s - 2020）

### 关键里程碑

| 时期 | 事件 | 影响 |
|------|------|------|
| 2012 | 深度学习在 ImageNet 取得突破 | 计算机视觉飞跃 |
| 2017 | Transformer 架构问世 | "Attention is All You Need" 改变一切 |
| 2018 | BERT 发布 | NLP 进入预训练时代 |
| 2019 | GPT-2 发布 | 文本生成能力令人惊叹 |
| 2020 | GPT-3 发布 | 少样本学习展示强大能力 |

### 阶段特点

- 理解能力大幅提升
- 但仍是"被动工具"，需要人类明确指令
- 不具备自主规划和工具使用能力

::: info 补一课：Agent 概念的学术奠基
智能体概念其实比大模型早得多：
- **1950** 图灵测试为"机器能否思考"设下标尺
- **1966** ELIZA 用约 150 行脚本模仿心理医生对话，制造了著名的"ELIZA 效应"——人容易把规则匹配当成理解
- **1980s** 明斯基《心智社会》提出"智能来自许多简单部件的协作"
- **1995** Wooldridge & Jennings 正式定义：Agent 是能自主行动以实现目标的计算机系统

这解释了为什么"多智能体协作"是有理论根基的，而不是炒作。
::: 

## 阶段三：大模型 Agent 爆发期（2021 - 至今）

### 关键里程碑

| 时期 | 事件 | 里程碑意义 |
|------|------|-----------|
| 2022.11 | ChatGPT 发布 | **引爆 AI 热潮**，展现强大对话能力 |
| 2023.03 | GPT-4 + Plugins | **首次实现工具调用**，Agent 雏形诞生 |
| 2023.03 | AutoGPT 开源 | 自主 Agent 概念验证，GitHub 爆火 |
| 2023.05 | LangChain、LlamaIndex 成熟 | Agent 开发框架完善 |
| 2024-2025 | 企业级 Agent 应用大规模落地 | 从概念走向生产力 |

### 阶段特点

- ✅ 真正的自主性
- ✅ 工具使用能力
- ✅ 任务规划和分解
- ✅ 多轮迭代优化

![规则-数据-行动三个时代，越走越自由](/images/ai-agent/history/03-three-eras.png)

::: tip 2025-2026 里程碑（本教程写作时点）
- **2023** 被称作 AI Agent 元年：GPT-4、AutoGPT 发布；Function Calling 让"大脑+四肢"落地；GPTs 确立"你是谁、你知道什么、你能做什么"的 Agent 结构
- **2025** 商业化元年：OpenAI Operator 上线、DeepSeek-R1 开源推理、Monica 发布通用 Agent 产品 **Manus**、"Vibe Coding" 兴起

::: 

## 多 Agent 协作模式

### 为什么需要多 Agent？

单一 Agent 有知识边界和能力限制。多 Agent 系统就像**一个团队**，每个 Agent 各司其职。

![一个调度幽灵拿着指挥棒，指挥三个拿不同工具的小幽灵](/images/ai-agent/history/02-multi-agent.png)

### 协作架构

```
                    ┌─────────────┐
                    │   Orchestrator │  ← 调度 Agent
                    │   调度中心      │
                    └───┬───┬───┬───┘
                        │   │   │
        ┌───────────────┼───┼───┼───────────────┐
        ▼               ▼   ▼   ▼               ▼
   ┌─────────┐    ┌─────────┐    ┌─────────┐
   │ Agent A  │    │ Agent B  │    │ Agent C  │
   │ 代码专家  │    │ 数据分析  │    │ 文档专家  │
   └─────────┘    └─────────┘    └─────────┘
```

### 协作模式类型

| 模式 | 描述 | 适用场景 |
|------|------|----------|
| **层级式** | 一个主 Agent 调度多个子 Agent | 复杂项目管理 |
| **流水线** | Agent A 输出 → Agent B 输入 | 数据处理管道 |
| **辩论式** | 多个 Agent 讨论达成共识 | 决策分析 |
| **竞争式** | 多个 Agent 并行竞赛选最优 | 创意生成 |

::: tip 关键洞察
多 Agent 协作不是简单的"堆 Agent"，而是要让每个 Agent 发挥专长、信息共享、协调一致。这需要优秀的架构设计和通信协议。
:::
