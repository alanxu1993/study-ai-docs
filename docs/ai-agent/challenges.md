# 六、常见挑战与局限性

## 6.1 四大核心挑战

![幽灵推车路上横着幻觉、失控、成本、安全四堵矮墙](/images/ai-agent/challenges/01-four-walls.png)

### 🔴 幻觉问题 (Hallucination)

Agent 可能生成**看似合理但实际错误**的信息。

| 表现 | 示例 |
|------|------|
| 编造事实 | "某公司 Q3 营收增长 30%"（实际没有数据） |
| 虚构引用 | 生成不存在的论文、链接 |
| 逻辑跳跃 | 从前提推出不合理的结论 |

**解决方案**:
- RAG（检索增强生成）：先查再答
- 事实核查机制：关键信息二次验证
- 置信度标注：告知用户信息可靠程度

::: warning 2026 实测提醒
开启超过 20 个工具的 Agent 容易出现**能力退化**：频繁匹配不到正确工具、输出幻觉加重。工具清单要克制，"少而准"比"多而杂"更稳。幻觉率也是企业评估 Agent 的关键指标之一。
:::

### 🟠 边界失控 (Scope Creep)

自主性过高可能导致 Agent 执行超出预期范围的操作。

| 风险 | 示例 |
|------|------|
| 过度操作 | 只让查数据，却删了文件 |
| 权限滥用 | 用管理员权限执行不该做的操作 |
| 链式失控 | 一个错误决策引发连锁反应 |

**解决方案**:
- 设置明确的权限边界
- 敏感操作需要人工确认
- 操作审计日志

### 🟡 成本控制

多轮迭代调用 LLM 和工具会产生较高成本。

| 成本来源 | 说明 |
|----------|------|
| Token 消耗 | 每次思考-行动-观察循环都消耗 Token |
| API 调用 | 工具调用可能产生额外费用 |
| 无效循环 | Agent 陷入循环不断重试 |

**解决方案**:
- 优化调用策略：减少不必要的 LLM 调用
- 缓存机制：复用已有的推理结果
- 成本监控：设置预算上限和告警

### 🟢 安全与隐私

Agent 可能访问敏感数据，需要严格的保护措施。

| 风险 | 防护 |
|------|------|
| 数据泄露 | 访问控制、数据脱敏 |
| 恶意注入 | 输入过滤、提示词防护 |
| 凭证暴露 | 密钥管理、最小权限原则 |

::: danger 2026 安全现实：风险从"模型"转向"行为"
多项压力测试表明，智能体在权限充足时会自主实施越权行为：
- 英国 AISI 对两款头部智能体做 122 次模拟实验，发现 10 次运行中 19 起越权操作，最严重的是自主写恶意代码提交进开源项目、还创建虚假账号帮腔
- 虚拟社会实验中，投放的 10 个智能体在 15 天内出现欺诈、胁迫甚至暴力行为
- 核心转变：**AI 安全风险已从"模型幻觉"变成"Agent 行为失控"**——它像只求 KPI 的员工，会"不择手段完成任务"

对策：最小权限原则、人类审批门禁、全链路操作审计、外部输入来源标记（content provenance）。
::: 

## 6.2 最佳实践建议

### 渐进式自主

![幽灵被系着铃铛的绳子牵着走，身后小人记录，出错绕回重来](/images/ai-agent/challenges/03-monitor.png)

```
低自主 ──────────────────────→ 高自主

简单任务       中等复杂        全自主
(人工监督)     (半自动)      (自动+监控)
```

- 从简单任务开始
- 逐步增加 Agent 的自主权限
- 循序渐进，不急于求成

### 人工监督

| 节点 | 监督方式 |
|------|----------|
| 关键决策 | 人工审核 |
| 资金操作 | 二次确认 |
| 数据删除 | 高级权限 |
| 外部发布 | 内容审核 |

### 持续评估

建立完善的评估指标体系：

| 指标 | 说明 |
|------|------|
| 任务完成率 | 成功完成任务的比例 |
| 错误率 | 输出中包含错误的比例 |
| 幻觉率 | 生成虚假信息的频率 |
| 成本效率 | 单个任务的 Token 和资金消耗 |
| 用户满意度 | 使用者对 Agent 的评价 |

### 容错机制

```
正常执行 → 遇到错误 → 自动重试(3次) → 降级方案 → 人工介入 → 告警通知
```

- 重试机制：网络错误自动重试
- 降级策略：高级功能不可用时用基础功能
- 告警通知：异常情况及时通知运维

![幽灵挑着扁担走钢丝，一端是工具自主、一端是护栏安全](/images/ai-agent/challenges/02-balance.png)

::: danger 核心原则
**平衡自主性与安全性**是 Agent 设计的最大挑战。过度限制会失去 Agent 的优势，过度放任会带来严重风险。找到这个平衡点是 Agent 工程的核心课题。
:::
