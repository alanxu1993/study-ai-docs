# Codex 记忆功能使用教程

每个 AI 编程会话最让人遗憾的时刻，是辛苦摸清的"项目来龙去脉"随着会话关闭而消失：这个模块为什么这么设计、那个坑为什么不能碰、上次重构定了什么约定。下次开新会话，Agent 又得从零开始问、从头摸索。Codex 的记忆功能正是为此而生——它把"从先前工作中学到的有用上下文"沉淀下来，跨会话延续，让 Agent 不只"会写代码"，还"记得这个项目"。这篇教程带你理解记忆的核心机制、掌握管理与安全边界。

## 一、记忆核心概念

### 1.1 什么是记忆（一句话懂）

记忆是 Codex 保存的"从先前工作中学到的有用上下文"——包括项目决策、结构约定、踩坑经验等局部信息，在后续会话中被自动读取，让新会话接续旧会话的认知。

### 1.2 记忆 vs AGENTS.md：分工而非重复

这是整个记忆系统最容易被误解的一点：记忆不是 AGENTS.md 的替代品，两者分工明确，各管一摊。

| 维度 | AGENTS.md | 记忆 |
| --- | --- | --- |
| 本质 | 项目级**指令文件**，塑造行为 | 从工作中**学习到的上下文** |
| 回答的问题 | "该**怎么做**"（规范、命令、约定） | "**之前发生了什么**"（决策、来龙去脉） |
| 来源 | 人写或 `/init` 脚手架 | Agent 从工作过程中沉淀 |
| 写入方式 | 显式编辑文件 | 显式保存消息/摘要（非自动全存） |
| 作用域 | 全局/仓库/子目录级联 | 按项目、按类型作用域 |

类比理解：AGENTS.md 是公司的《员工手册》，规定行为准则；记忆是员工的"工作笔记"，记录上次项目里踩过的坑和拍板的理由。手册决定"怎么做事"，笔记决定"我还记得什么"。

![记忆与 AGENTS.md 分工](/images/codex/memory/01-memory-vs-agentsmd.png)

::: tip 一句话区分
当一个信息是"规则"（以后任何会话都该遵守）→ 写 AGENTS.md；当一个信息是"事实"（这个项目上一次发生了什么）→ 存记忆。写反了，规则会被遗忘，事实会被过度泛化。
:::

## 二、查看与管理记忆

### 2.1 /memories 斜杠命令

在 Codex 会话中直接输入 `/memories`，即可查看当前会话可用的记忆列表，确认"Agent 现在还记得什么"。这是排查"Agent 为什么不知道 X"的第一步——先看记忆里到底存了什么。

### 2.2 按项目作用域

记忆按项目隔离：不同项目的记忆互不串扰，A 项目的决策不会泄漏进 B 项目。这让同一个账号同时维护多个仓库时，上下文保持干净。

| 作用域 | 覆盖范围 | 适用 |
| --- | --- | --- |
| 项目作用域 | 单个项目/仓库 | 最常用，隔离清晰 |
| 类型作用域 | 按"定义/决策/私密偏好"等类型 | 细粒度控制读取与写入 |

### 2.3 按类型作用域：读写范围控制

记忆支持**按类型作用域**控制读写范围——不同类型的记忆对 Agent 的可见性不同。典型示例：允许 Agent 读取"定义与决策"类记忆（项目怎么定义的、为什么这么决定），但不允许读取"私密偏好"类记忆。

![记忆按项目与类型作用域](/images/codex/memory/02-memory-scope.png)

```text
允许读取：项目定义、技术决策、结构约定
禁止读取：个人私密偏好、账号信息、敏感配置
```

::: warning 作用域是安全的第一道闸门
记忆的读取权限**严格受作用域约束**。私密信息放进"不可读"作用域后，Agent 就不会主动读取——但请务必把敏感信息**本身就不写进记忆**，作用域只是兜底防线，不是保险箱。
:::

## 三、记忆如何产生

### 3.1 ChatGPT / Codex 共享上下文

记忆并非 Codex 独有：ChatGPT 与 Codex 共享上下文机制。你在 ChatGPT 中显式保存的消息/摘要，可以作为项目记忆在 Codex 会话中继续使用，反之亦然。这套共享体系让"同一套认知"在聊天与编程之间无缝迁移。

### 3.2 显式保存，而非自动全存

记忆不是流水账——**Codex 不会自动把每个会话的全部内容都存进记忆**，而是依赖显式保存。这是刻意设计：全量自动存储会灌入大量噪音，反而稀释真正有价值的上下文。

需要存记忆的典型时刻：

- 一个重要技术决策拍板后（"为什么选方案 B 而非 A"）；
- 一次排查告一段落后（"这个报错的根因与规避方式"）；
- 项目结构约定确立后（"公共工具类都在 src/utils/，别新建"）。

### 3.3 总结存储

实践上建议**先总结、再保存**：把一段对话压缩成 2-3 句结论存入记忆，而非保存原始对话。总结后的记忆体积小、信噪比高，后续被读取时的价值远大于"整段对话原文"。

![记忆保存与查看流程](/images/codex/memory/03-memory-manage.png)

::: tip 存储习惯
"完成即总结，总结即保存"。每次任务收尾时花 30 秒问一句："这次我知道了什么以后还会用到的信息？"把它写成一句话存进记忆——这是记忆系统的最高性价比用法。
:::

## 四、记忆安全与隐私

### 4.1 作用域限制

记忆安全的根基是**最小化暴露**：

- **定义/决策可读**：项目定义、技术决策类记忆对 Agent 可见，用于维持工作连续性；
- **私密偏好不可读**：个人偏好、隐私信息放在 Agent 不可读的作用域，避免被主动调用；
- **写入同样受限**：读写范围双向控制，不是只控制"读"。

### 4.2 IDE 会话只读记忆

在 IDE（如 VS Code 等编辑器集成）中，会话对记忆的访问是**只读**的——IDE 会话可以读取记忆来延续上下文，但不能写入。这意味着 IDE 里的临时探索不会污染长期记忆，同时也提醒你：正式的"存记忆"动作要在具备写权限的终端会话里完成。

| 会话类型 | 读记忆 | 写记忆 |
| --- | --- | --- |
| 终端 CLI 会话 | 支持 | 支持 |
| IDE 集成会话 | 支持（只读） | 不支持 |
| ChatGPT 共享上下文 | 支持 | 支持（显式保存） |

## 五、实战案例：跨会话延续项目上下文

**场景**：某项目周五用 Codex 完成了"将遗留 XML 配置迁移到 YAML"，期间摸清了：迁移脚本在 `scripts/migrate.py`、旧的 XML 仍被 `legacy` 目录引用、团队约定迁移后旧文件保留两周再删。

**没有记忆时**：周一开始新会话处理后续任务，Agent 对上述事实一无所知，会重新问"XML 配置在哪""迁移脚本叫什么"，甚至可能建议"直接删掉 legacy 目录"——触发灾难。

**有记忆时**：

1. 周五收尾，把结论总结为："XML→YAML 迁移已完成；迁移脚本 scripts/migrate.py；legacy 目录保留两周后删除"并保存到项目记忆；
2. 周一新会话，Agent 自动读到记忆，直接衔接"迁移后清理 legacy 目录"的任务，不再重复摸底；
3. 若期间有队友问"迁移脚本在哪"，记忆让 Agent 能立即给出准确答案。

这个案例展示了记忆的三种价值：**免重复劳动、防误操作、信息即答**。

## 六、最佳实践与常见问题

### 6.1 最佳实践清单

- **存结论不存流水**：总结后再保存，控制记忆体积与信噪比；
- **区分规则与事实**：规则写 AGENTS.md，事实存记忆，各归其位；
- **常用 `/memories` 自查**：新会话开工前先确认 Agent 记得什么，防"失忆"；
- **敏感信息绝不进记忆**：作用域只是兜底，源头不写最安全；
- **善用共享上下文**：ChatGPT 里沉淀的结论，在 Codex 编程会话里复用。

### 6.2 常见问题排查

| 现象 | 可能原因 | 排查步骤 |
| --- | --- | --- |
| Agent 不记得上次的决定 | 未显式保存，或保存到错误作用域 | 用 `/memories` 查看；确认保存了总结而非只靠自动 |
| 记忆里混入其他项目信息 | 作用域配置不当 | 检查按项目作用域是否隔离正确 |
| IDE 里想存记忆却存不了 | IDE 会话只读 | 到终端 CLI 会话完成写入 |
| Agent 读到了不该读的信息 | 类型作用域未限制 | 把私密偏好移到不可读作用域，并从源头删除 |
| 记忆太乱找不到重点 | 全量保存了流水 | 养成"总结后保存"习惯，定期清理低价值记忆 |

## 七、总结

Codex 记忆的核心价值是**让上下文跨会话延续**：它和 AGENTS.md 明确分工——AGENTS.md 管"怎么做"的规则，记忆管"之前发生了什么"的事实；它靠**显式保存 + 总结存储**保证质量，靠**项目作用域 + 类型作用域**保证隔离与安全，并在 IDE 会话中以只读方式受限访问。用好记忆，你的 Codex 会从"每次都是新员工"变成"记得项目前世今生的老搭档"。
