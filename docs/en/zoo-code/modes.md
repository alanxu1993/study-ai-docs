# 三、Zoo Code 模式与工作流

Zoo Code 适应你的工作方式，而不是反过来。它提供五种工作模式：

## 模式概览

| 模式 | 用途 | 典型场景 |
|------|------|----------|
| **Code Mode** | 日常编码、编辑和文件操作 | 写功能、改代码、操作文件 |
| **Architect Mode** | 规划系统架构、规格说明和迁移方案 | 系统设计、技术方案讨论 |
| **Ask Mode** | 快速获取答案、代码解释和文档 | 查问题、读代码、写文档 |
| **Debug Mode** | 追踪问题、添加日志、隔离根本原因 | 调试 Bug、排查线上问题 |
| **Orchestrator Mode** | 把大任务拆成子任务，委派给多个子代理 | 复杂项目、并行任务 |
| **Custom Modes** | 为团队或特定工作流构建自定义模式 | 标准化团队开发流程 |

## Code Mode — 日常编码

这是最常用的模式。在此模式下 Zoo Code 可以：

- 创建新文件和目录
- 编辑现有文件
- 执行终端命令
- 安装依赖包
- 运行测试

## Architect Mode — 架构规划

在动手写代码之前，先用 Architect Mode 规划：

- 分析现有代码库架构
- 提出技术方案和选型建议
- 设计模块划分和接口
- 规划数据库表结构
- 讨论迁移策略

该模式下 Zoo Code 不会直接修改文件，而是输出分析报告和规划方案。

## Ask Mode — 问答与学习

纯问答模式，用于：

- 解释代码逻辑
- 查阅 API 文档
- 理解设计模式
- 回答技术问题

该模式不会修改任何文件。

## Debug Mode — 调试追踪

针对调试场景优化：

- 分析错误堆栈
- 添加调试日志
- 定位 Bug 根因
- 提出修复方案
- 验证修复效果

## Orchestrator Mode — 多代理编排

Orchestrator 是 Zoo Code 的任务编排系统，也是它区别于普通编码助手的关键能力：

1. **父代理规划**：父代理把大任务分解为相互独立的子任务
2. **委派子代理**：每个子任务分发给拥有独立上下文窗口的子代理（subagent），通常会切换到 Code 等执行模式
3. **隔离执行**：子代理之间有严格的权限隔离，互不干扰
4. **结果汇总**：子代理完成后只向父代理返回摘要，父代理不会被实现细节塞满上下文
5. **失败恢复**：某项子任务失败时，可自动恢复或回滚，不影响其他任务

这一设计源自 Roo Code 的 **Boomerang 任务**模式，解决了单一上下文窗口被占满的问题，让你能在 VS Code 内编排一个真正并行的"AI 开发团队"。

## Custom Modes — 自定义模式

为团队定制标准化工作流：

- 定义模式名称和角色提示词
- 限制可用的工具和操作
- 绑定特定 MCP 服务器
- 设置模型推理参数

自定义模式可保存在项目根目录的 `.roomodes` 文件中随仓库分发。一个常见实践是定义 `Planner → Coder → Tester → Reviewer` 的流水线 Agent，每个 Agent 只拥有自己需要的工具权限。详细使用请参考 [自定义模式文档](https://docs.zoocode.dev/advanced-usage/custom-modes)。

## 推荐工作流

对于中等以上复杂度的任务，推荐这样组合使用：

1. **Architect Mode** 完成方案设计
2. **Orchestrator Mode** 拆解任务并并行执行
3. **Code Mode** 处理日常编码
4. **Debug Mode** 排查问题
5. **Review** 审查所有变更后再提交
