# Hermes Agent 电脑操控使用教程

> 来源：[Hermes Agent 官方文档](https://hermes-agent.nousresearch.com/docs/zh-Hans/) · [GitHub: NousResearch/hermes-agent](https://github.com/NousResearch/hermes-agent)

让 Agent 只能操作文件、跑终端，它始终隔着"命令行"这层玻璃看世界。Hermes Agent 的电脑操控（Computer Use）能力让它**真的能"看"和"操作"电脑**：用视觉模型看懂截图、控制桌面窗口、驱动浏览器点按钮填表单——就像你坐在电脑前一样干活。自动化的边界从此从"文本世界"扩展到"图形界面世界"：网页自动化、桌面任务、截图分析，一句自然语言即可。本章带你走通桌面操控、浏览器自动化、视觉分析三条主线。

## 一、computer-use-linux：Linux 桌面控制

### 1.1 什么是 computer-use-linux（一句话懂）

`computer-use-linux` 是 Hermes 的 **Linux 桌面控制 MCP server**：它让 Agent 能像人一样操控 Linux 桌面——读取屏幕内容、移动点击鼠标、敲键盘输入、定位并操作窗口。类比理解：它给 Agent 装上"眼睛"（看屏幕）和"手"（输入），实现对图形界面的完整操控。

它的技术底座由四块拼成：

| 能力模块 | 技术手段 | 作用 |
| --- | --- | --- |
| 界面理解 | **AT-SPI 无障碍树** | 读取桌面控件的语义结构（按钮、输入框、窗口），比纯截图更精准 |
| 输入控制 | **Wayland / X11 输入** | 通过显示协议注入鼠标、键盘事件，模拟真实操作 |
| 视觉感知 | **截图** | 抓取屏幕画面供视觉模型分析 |
| 窗口管理 | **合成器窗口定位** | 通过合成器（compositor）定位、聚焦、移动窗口 |

### 1.2 工作流程

一个典型的桌面操控任务长这样：

```text
打开 LibreOffice Writer，新建文档，输入"你好，Hermes"，保存为 report.odt。
```

Hermes 会：用无障碍树找到"打开应用"入口 → 定位 Writer 窗口 → 用输入注入完成打字 → 走菜单保存。整个过程它在屏幕的"所见"与界面的"所控"之间来回校正，像人一样边看边操作。

::: warning 平台限制
`computer-use-linux` 定位的是 **Linux 桌面**环境。如果你跑在 Windows / macOS 上，请优先使用 `browser` 工具集做浏览器内自动化，桌面级操控的跨平台支持以官方文档为准。
:::

## 二、browser 工具集：浏览器自动化

### 2.1 三种浏览器引擎

`browser` 工具集负责**浏览器自动化**——导航、点击、输入、截图。它支持三种驱动引擎，按需求任选：

| 引擎 | 特点 | 适合场景 |
| --- | --- | --- |
| **Browserbase** | 云端浏览器，可并行、可持久 | 大规模网页抓取、需要远程环境 |
| **Camofox** | 反检测浏览器，伪装成普通用户 | 有反爬/风控的站点 |
| **本地 Chromium** | 本机浏览器，数据不出本机 | 日常网页操作、登录态复用 |

### 2.2 常用操作

- **导航**：打开 URL、等待页面加载；
- **点击**：定位并点击按钮、链接、下拉选项；
- **输入**：在表单中填写文本、提交；
- **截图**：截取整页或元素，回传视觉模型分析。

对话示意：

```text
打开 https://example.com/login，用测试账号登录，进入后台把今天的报表截图发我。
```

Hermes 依次导航 → 定位登录框 → 输入凭据 → 点击登录 → 跳转 → 截图并交给 `vision` 分析总结，一气呵成。

### 2.3 与 computer-use 的分工

两者并不冲突，而是分工：**网页内的操作交给 `browser`（更快更稳，直接操作 DOM）；桌面级应用、跨应用流程交给 `computer-use-linux`（操控整个桌面）**。需要浏览器以外的系统操作时，才动用桌面控制。

## 三、vision 视觉分析：让 Agent 看懂画面

### 3.1 视觉工具集

`vision` 工具集给 Hermes 装上"看懂画面的能力"：接受截图或图像输入，让具备视觉能力的模型理解画面内容——识别文字、判断状态、描述元素、定位目标。

```text
这张截图里表单的哪个字段校验失败了？帮我读一下报错信息。
```

Hermes 把截图交给 `vision`，提取出错信息和位置，再决定如何修正。它是 `browser` 与 `computer-use` 的**眼睛**：桌面/浏览器负责操作，`vision` 负责确认"操作的结果对不对"。

### 3.2 图像输入与截图理解

- **截图理解**：把当前界面截图 → 视觉模型解读 → 指导下一步操作，形成"看-想-动"闭环；
- **图像输入**：你可以把本地图片、设计稿、报错截图直接喂给 Hermes，让它基于画面回答或执行任务。

::: tip 视觉与操作配合
最好的实践是**"操作 + 验证"循环**：操作一步 → 截图 → vision 校验结果 → 不对就修正。比盲目点到底可靠得多，也最接近人的工作方式。
:::

## 四、实战案例

### 4.1 场景一：自动化网页操作

用 `browser` + `vision` 完成一次网页端到端任务：

```text
打开后台，按日期筛选订单，把金额排序后导出 CSV，并核对导出行数与页面显示一致。
```

导航、筛选、排序、导出由 `browser` 完成，行数核对由 `vision` 读截图确认——一次操作 + 一次验证，把"导出后要人工对一遍"的环节也省掉了。

### 4.2 场景二：桌面任务

用 `computer-use-linux` 处理桌面级任务：

```text
把桌面上的 5 个 PDF 合并成一个，转成 PDF 放到 ~/output 里。
```

Agent 通过桌面 UI 打开处理应用（或调用对应工具），完成合并转换，全程可视化可控。

### 4.3 场景三：截图分析

```text
分析这张 UI 设计稿：布局分几块、主色是什么、有什么交互缺陷建议。
```

无需任何"操作"，把截图丢给 `vision` 即可获得结构化分析——设计评审、Bug 复现描述、竞品页面拆解都能这样处理。

## 五、研究特性：批量轨迹生成

Hermes 还提供面向研究的**批量轨迹生成与压缩**特性：可以成批地生成"操作轨迹"（Agent 一步步执行任务的完整记录），并把长轨迹**压缩**成精简版本。

| 用途 | 说明 |
| --- | --- |
| 训练数据 | 为**训练工具调用模型**（tool-calling LLM）提供高质量轨迹样本 |
| 行为研究 | 观察 Agent 如何决策、何时失误，改进提示与工具设计 |
| 流程沉淀 | 把稳定的操作轨迹整理为可复用的技能流程 |

这是偏进阶/研究向的能力，普通用户用不到也不必焦虑——了解即可，需要时以官方文档为准。

## 六、安全注意事项

电脑操控意味着 Agent 能"动你的鼠标键盘、看你的屏幕"——这是一等一的敏感权限，务必注意：

::: danger 权限边界要划清
- **输入注入可造成真实后果**：点击"删除""转账""发送"这类按钮是真实的操作，务必确保任务边界清晰，不要在未确认的站点上放权；
- **截图像素含敏感信息**：`vision` 读图会把画面内容送入模型，涉及密码、密钥、隐私数据的画面慎截；
- **先读后动**：让 Agent 先截图、朗读它看到的内容，确认无误后再执行点击/输入等有副作用的操作。
:::

## 七、最佳实践与常见问题

### 7.1 最佳实践

1. **网页优先浏览器、桌面才用 computer-use**：能 DOM 操作就别走像素级点击，快且稳；
2. **每一步截图验证**：操作 → 截图 → vision 确认，形成闭环；
3. **需要反爬选 Camofox、大规模选 Browserbase、日常用本地 Chromium**：按场景挑引擎；
4. **敏感操作前先让 Agent 汇报"它看到了什么、打算做什么"**。

### 7.2 常见问题排查

| 问题 | 排查步骤 |
| --- | --- |
| 桌面操控无反应 | ① 确认环境是 Linux + 已启用对应显示协议（Wayland/X11）；② 检查 MCP server 是否正常启动；③ 确认无障碍（AT-SPI）服务可用 |
| 浏览器元素点不到 | ① 换更稳定的选择器/等页面加载完成；② 先截图确认元素是否真实存在；③ 有反爬时改用 Camofox |
| 截图里内容识别不准 | 检查模型是否启用视觉能力；放大/裁切关键区域再分析 |
| 工具未启用 | 运行 `hermes tools` 确认 `browser`、`vision`、`computer-use-linux` 已勾选 |
| 云端浏览器连不上 | 检查 Browserbase 等服务的密钥与网络，必要时回退本地 Chromium |

## 总结

Hermes 的电脑操控能力，是把"桌面（computer-use-linux）+ 浏览器（browser）+ 视觉（vision）"三件套组合成一套**看-想-动-验**的自动化闭环：能看懂界面、能操作界面、能确认结果。网页自动化、桌面任务、截图分析三大场景都能覆盖，批量轨迹生成还为训练工具调用模型提供了研究级素材。使用时牢记**权限边界与"先读后动"**——它越能干，越要守住安全底线。
