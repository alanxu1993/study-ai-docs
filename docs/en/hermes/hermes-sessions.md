# Hermes Agent 会话使用教程

工具让 Hermes"会干活"，但活儿是一次次干完的——每一次交互，都发生在一个**会话（Session）**里。很多人用得困惑：为什么聊着聊着它就"忘"了前面的话？为什么关掉终端就接不上？一次性的 `-q` 和交互式 `hermes` 到底什么区别？答案都在会话机制里。会话是 Agent 的工作单元：它承载上下文、记录多轮工具调用、决定哪些内容能被记忆沉淀。理解会话，你就能让长任务不断线、后台任务不阻塞、上下文不被浪费。本章从核心概念讲起，给你一套直接能用的 TUI 技巧、续传方法与斜杠命令清单。

## 一、会话核心概念

### 1.1 什么是会话：Agent 的"工作单元"

会话是 Hermes 组织一次对话的最小工作单元，包含你的输入、Agent 的回复、期间的工具调用及其结果，以及支撑这一切的上下文窗口。**会话 = 一段连续交互的状态容器**。

会话内的信息（尤其工具调用结果）会占用上下文窗口，这决定了两个结论：一是 Hermes 要求模型至少支持 **64K tokens 上下文**，否则多轮工具调用撑不住；二是"何时结束会话、何时续传"需要经营。

### 1.2 两种会话形态：交互式 TUI 与一次性对话

| 形态 | 命令 | 特点 | 适合 |
| --- | --- | --- | --- |
| 交互式 TUI | `hermes`（或 `hermes --tui`） | 完整终端界面，多轮对话、斜杠命令、历史 | 日常开发、多步任务 |
| 一次性对话 | `hermes chat -q "..."` | 单次问答即结束，不保留交互 | 脚本、CI、快速查一下 |
| 断点续传 | `hermes --continue` | 恢复上次会话接着聊 | 长任务中断后找回 |

::: tip 类比理解
交互式 TUI 像开一个"工作台"，你在上面连续作业；一次性 `-q` 像打一通"电话"，说完挂断，下回重新拨号。需要连续上下文的工作，务必用 TUI。
:::

### 1.3 会话的完整生命周期

一次完整会话大致经历：**创建会话 → 载入上下文 → 多轮交互（含工具调用）→ 结束/暂存 → 可续传**。

![会话的完整生命周期](/images/hermes/sessions/01-session-flow.png)

- **创建**：运行 `hermes` 启动新会话。
- **载入上下文**：系统提示、SOUL.md 个性、项目上下文文件、记忆注入会话开头，决定 Agent"懂多少背景"。
- **多轮交互**：你提问、Agent 思考并可能调用工具，结果回流驱动下一轮。
- **结束/暂存**：退出后会话持久化保存（数据都在 `~/.hermes/` 下）。
- **续传**：`hermes --continue` 从上次断点接着跑。

理解这个生命周期，你就明白"记忆是跨会话的，上下文是会话内的"——详见第六节。

## 二、TUI 使用技巧

`hermes` 的交互式终端界面（TUI）是日常主力，官方推荐 `--tui` 现代终端界面：

```bash
hermes --tui    # 现代终端界面（推荐）
hermes          # 交互式 CLI 开始对话
```

- **多行编辑**：复杂 prompt 直接换行书写再提交，长文本表达能力是质变（对比 `-q` 只能塞一行字符串）。
- **斜杠命令补全**：输入 `/` 弹出补全列表，不用死记命令名。
- **历史记录**：上下键翻看之前输入过的消息，重发或微调很顺手。
- **流式工具输出**：工具输出**流式**显示在界面，你能实时看到它在跑什么，一眼看出 Agent 卡在哪个工具上。

::: tip 为什么 TUI 值得用？
一次性 `-q` 只能拿最终结果；TUI 能看到每一步动作。调试工具链、观察 Agent 思考路径时，流式输出比任何日志都直观。
:::

## 三、会话续传：长任务不断线

### 3.1 断点续传：`hermes --continue`

中途退出、终端崩了、想歇会再继续——Hermes 会保存上次会话，一条命令接着聊：

```bash
# 上次会话在哪里断的，就从哪里继续
hermes --continue
```

![断点续传恢复会话](/images/hermes/sessions/02-continue.png)

续传的价值：**上下文不丢**。工具调用的中间结果、Agent 已做的规划都还在，不用重新交代背景。长任务（多文件重构、持续调研）强烈依赖它。

### 3.2 一次性对话：`hermes chat -q`

不需要交互、只要一个答案时，用一次性对话最干脆：

```bash
hermes chat -q "解释一下 Hermes 的 delegation 工具是做什么的"
```

**特点**：单次问答，跑完即结束。**适合**：脚本调用、CI 集成、快速查事实。**不适合**：需要多轮追问、依赖前面上下文的连续任务。

::: warning 一次性会话没有"上一轮"
`-q` 每次都是全新上下文，Agent 不记得你之前问过什么。发现"它怎么把我刚说的忘了"，大概率是用错成 `-q` 了——改用 TUI 交互式会话即可。
:::

## 四、后台任务：不阻塞会话

耗时长的任务（大批量调研、长文档生成）不想占着当前会话干等，用 `/background` 丢到后台：

```bash
/background 帮我调研这三篇文章并各写 100 字摘要，完成后告诉我
```

后台任务独立运行，你可以继续当前会话做别的事；完成后收到结果通知，再决定是否回当前会话处理。

::: tip 后台任务 + 消息网关是绝配
配合 Telegram、Discord 等消息网关，后台任务跑完直接推送结果到手机，人完全不用守着终端。
:::

## 五、常用斜杠命令

TUI 内的斜杠命令是会话的"控制面板"，最常用的几个：

| 命令 | 作用 | 使用场景 |
| --- | --- | --- |
| `/model <name>` | 切换 LLM 模型 | 中途想换更聪明的模型 |
| `/memory` | 查看/管理记忆 | 检查 Agent 记住了你什么 |
| `/skills` | 查看/管理技能 | 浏览自进化技能 |
| `/cron` | 管理定时任务 | 新增/查看/暂停 cron |
| `/help` | 帮助 | 忘了命令时快速查看 |
| `/background <prompt>` | 启动后台任务 | 长任务不阻塞当前会话 |

```bash
# 会话内直接切到更强的模型
/model anthropic/claude-opus-4.6
```

::: tip 记不住就敲 `/`
斜杠命令有补全，输入 `/` 弹出的列表里挑即可，不用背全量清单。遇到未知命令先 `/help`。
:::

## 六、会话上下文与记忆的关系

这是最容易混淆的一组概念，也是用好 Hermes 的分水岭：

| 维度 | 会话上下文 | 持久记忆 |
| --- | --- | --- |
| 存活范围 | 会话内 | 跨会话 |
| 内容 | 本轮对话 + 工具结果 + 系统提示/SOUL/上下文文件 | 重要事实（`MEMORY.md`、`USER.md` 等） |
| 存储位置 | 上下文窗口（临时） | `~/.hermes/memories/`（持久） |
| 谁会读 | 当前会话的模型 | 每个新会话都会注入 |

**关系**：会话结束时上下文消散，只有被 Agent 判断"值得记住"的内容写入记忆，在下一会话开头重新注入。所以新会话里它忘了细节，却记得你的偏好——因为偏好进了记忆，细节留在上一个会话的上下文里。

::: tip 想让关键信息跨会话保留？
任务末尾明确说"请记住：我是谁 / 我偏好什么 / 这个项目用什么技术栈"。Agent 会写入记忆，下次新会话它就"还记得你"。
:::

## 七、最佳实践与常见问题

### 7.1 最佳实践

1. **长任务用 TUI + 续传**：连续作业用 `hermes`，中断后用 `hermes --continue`，别用 `-q` 硬拼。
2. **后台任务不占会话**：耗时任务丢 `/background`。
3. **会内切换模型**：觉得不够聪明就 `/model` 现场切，不用重开会话。
4. **把结论交给记忆**：重要结论明确让 Agent 写入记忆，别依赖"这次会话还记得"。
5. **敏感信息不入 prompt**：密钥放 `~/.hermes/.env`，会话会被保存。

### 7.2 常见问题排查

| 问题 | 排查步骤 |
| --- | --- |
| Agent"忘了"前面的话 | 确认是否用了 `-q`（每次全新上下文）；长任务接近上下文上限时用 `--continue` 续传衔接 |
| 上下文溢出 / 越聊越笨 | 上下文被长工具输出占满。拆任务、删大输出、适时结束会话并 `--continue` 开新一轮 |
| 关掉终端再打开接不上 | 用 `hermes --continue` 恢复；确认 `~/.hermes/` 下会话数据未被清理 |
| 一次性 `-q` 结果不对 | `-q` 无多轮纠错，复杂任务改用交互式会话，让 Agent 能调用工具自查 |
| 后台任务结果没看到 | 确认平台/网关通知通道，留意 TUI 里的完成提示 |
| 想彻底重置会话 | 结束会话重新 `hermes` 开新会话；注意记忆是跨会话的，重置会话不等于清记忆 |

::: warning 上下文溢出是"会话变笨"的头号原因
会话越长、工具输出越多，留给"思考"的空间越少，Agent 会显得迟钝、遗忘。对策不是硬撑一条超长会话，而是**拆段 + 续传**：一段会话干完一批活，`--continue` 接着下一批，让上下文保持清爽。这也是 Hermes 要求 64K+ 上下文的原因——它是多轮工具调用和长会话的底线保障。
:::

## 八、总结

会话是 Hermes 的工作单元，也是"上下文如何来、如何去、如何续"的载体。你已掌握：交互式 TUI（`hermes` / `hermes --tui`）适合多步任务，一次性 `hermes chat -q` 适合快速问答，`hermes --continue` 让长任务断点续传；TUI 里多行编辑、斜杠补全、历史记录、流式工具输出四招提升效率；`/background` 把长任务丢后台不阻塞会话；`/model`、`/memory`、`/skills`、`/cron`、`/help` 构成常用控制面板；关键是分清"上下文在会话内、记忆跨会话"，用"拆段 + 续传"对抗上下文溢出。把这些串起来，你就能让 Hermes 在一次又一次会话里持续、稳定、可续地为你干活——这正是"和你一起成长的 Agent"的工作方式。
