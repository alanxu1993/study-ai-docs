# 二、AI Agent 的构成

> 像人一样思考与行动

一个功能完整的 AI Agent 通常模仿人类的认知和行动循环，包含以下几个关键模块。

## 2.1 规划模块：任务的大脑与指挥官

这是 Agent 的**思考中枢**。它负责将用户模糊的、高层的目标分解成一系列清晰的、可执行的子任务步骤。

![幽灵把大目标用绳子拉成一排小步骤台阶](/images/ai-agent/components/01-planning.png)

### 任务分解示例

用户目标：**"分析公司上季度的销售数据"**

```
步骤 1: 连接数据库
步骤 2: 提取 Q3 销售数据
步骤 3: 按产品和地区分类
步骤 4: 计算环比增长率
步骤 5: 生成可视化图表
```

### 反思与调整

Agent 会评估每一步行动的结果：

- ❌ **数据库连不上** → 反思原因 → 尝试另一种连接方式或请求用户提供密码
- ❌ **数据格式不对** → 调整解析策略 → 重新处理
- ✅ **顺利获取数据** → 继续下一步

::: tip 规划能力决定了 Agent 的上限
一个只会执行单个指令的 AI 是"工具"，一个能拆解复杂任务、反思调整的 AI 才是"Agent"。规划模块的质量直接影响 Agent 解决复杂问题的能力。
:::

> **现实中的规划实现**：最主流的是 **ReAct 循环**（思考 → 行动 → 观察），以及基于它演化的 **Plan-and-Execute**（先列整体计划再逐步执行）和 **Tree of Thoughts**（同时探索多条思路）。2023 年 Google 提出 ReAct 时验证它比直接回答的准确率高出 30%-50%。

## 2.2 记忆模块：经验的笔记本

Agent 需要有记忆才能进行连贯的、基于上下文的对话和操作。

![幽灵抱着一本"刚才说啥"的笔记本，把内容归档进"越用越聪明"的大仓库](/images/ai-agent/components/02-memory.png)

### 短期记忆

- 记住当前对话的上下文
- 确保回答不跑题
- 理解前文的指令和结果

### 长期记忆

- 将重要的交互信息存储到数据库或向量数据库中
- 学到的知识可跨会话复用
- 实现**越用越聪明**

### 记忆架构对比

| 类型 | 存储方式 | 生命周期 | 示例 |
|------|----------|----------|------|
| 短期记忆 | 上下文窗口 | 当前会话 | "刚才你说了要分析 Q3 数据" |
| 长期记忆 | 向量数据库/SQL | 永久 | "用户偏好柱状图而非饼图" |

::: tip 更细的记忆分类（2026 前沿）
工程实践里常把记忆拆成四类访问模式，而不是四个独立系统：
- **工作记忆**：当前正在推理的对话和草稿
- **语义记忆**：关于用户、实体、世界的持久事实（偏好、定义）
- **情景记忆**：过去某次会话发生了什么、尝试过什么
- **程序记忆**：行为规则、指导方针、学到的做事流程

记忆系统的设计要点是**统一底座 + 分层访问**：会话缓冲 + 用户画像 KV 存储 + 向量长期库 + 知识图谱。向量数据库（Milvus、pgvector、Cosmos DB 等）是长期记忆的存储核心。
:::

## 2.3 工具调用模块：灵活的双手

这是 Agent 从**思考者**变为**行动者**的关键。通过 API 调用外部工具来扩展自身能力。

![幽灵把线插进搜索、代码、数据库三个插座，插上就是行动者](/images/ai-agent/components/03-tools.png)

::: info 从 Function Calling 到 MCP
2023 年 6 月 OpenAI 发布 **Function Calling**，让模型输出结构化 JSON 调用工具，"大脑+四肢"的架构第一次成为现实。2024 年 11 月 Anthropic 发布 **MCP（Model Context Protocol）**，把工具统一成可插拔的协议标准——一个工具做一次，就能在 LangChain、Claude、AutoGen 等之间通用。2025 年 MCP 捐赠给 Linux 基金会，成为工具层事实标准（月下载量近亿次）。开发者开始"针对协议接口"而非"针对某个框架 API"写 Agent 逻辑。
:::

### 常见工具类型

```
┌──────────────────────────────────────────────┐
│              Agent 工具生态                    │
├──────────┬──────────┬──────────┬─────────────┤
│  🔍 搜索  │  💻 代码  │  🗄️ 数据 │  🔌 API    │
│ 联网查询  │ 运行代码  │ 数据操作  │ 外部服务    │
├──────────┼──────────┼──────────┼─────────────┤
│ Google   │ Python   │ MySQL    │ 邮件发送    │
│ Bing     │ JS 沙箱  │ Redis    │ 表格操作    │
│ 知识库   │ 代码解释 │ 向量搜索  │ 智能家居    │
└──────────┴──────────┴──────────┴─────────────┘
```

### 工具调用的实际意义

| 没有工具调用的 AI | 有工具调用的 Agent |
|-------------------|-------------------|
| "我无法查询实时信息" | 自动搜索最新数据 |
| "我无法处理你的文件" | 读取并分析文件 |
| "请手动执行这些操作" | 自动调用 API 完成 |
| 知识截止于训练日期 | 实时获取最新信息 |

## 三大模块的协同

```
用户输入 → 规划模块（拆解任务）
              ↓
         记忆模块（检索上下文）
              ↓
         工具调用（执行子任务）
              ↓
         规划模块（评估结果）
              ↓
         返回最终答案
```

::: info 协同是关键
三个模块不是独立运行的，而是在 ReAct 循环中紧密配合：规划决定用什么工具，记忆提供背景信息，工具执行具体操作，结果反馈给规划进行下一步决策。
:::
