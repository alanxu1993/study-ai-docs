# Hermes 代理技能使用教程

> 来源：[Hermes Agent 官方文档](https://hermes-agent.nousresearch.com/docs/zh-Hans/) · [GitHub: NousResearch/hermes-agent](https://github.com/NousResearch/hermes-agent)

传统的 Agent 是"一次性消耗品"：任务做完，经验也就散了，下次遇到同类任务，又从零开始摸索。而 Hermes 最独特的能力，是**自进化技能（Skills）**——它会在完成任务后**自动把经验沉淀成技能**，甚至自己动手写技能文件。换句话说，别人的 Agent 是"请来的临时工"，Hermes 是"会写操作手册的老员工"。本章带你理解这套自进化机制，并学会手动编写、管理、复用技能。

## 一、技能系统核心概念

### 1.1 什么是技能（一句话懂）

**技能（Skill）**是 Agent 可复用的一组"操作步骤"，以 `SKILL.md` 为格式载体，存放在 `~/.hermes/skills/` 等目录，跨会话长期存在。它本质上是**程序性记忆**——"遇到这类任务该怎么做"的清单。

类比理解：记忆像**词条**（事实），技能像**菜谱**（流程）。菜谱一旦写下来，任何厨师照着做都能复现同样的味道。Hermes 会自己写菜谱，还能在反复做菜中不断改进它。

### 1.2 自进化循环

Hermes 的技能体系是一条自动循环：

```
完成任务 → 提炼步骤 → 生成/改进 SKILL.md → 下次同类任务自动调用 → 再用再改进
```

- **自动创建**：完成一个此前没做过、但有复用价值的任务后，Hermes 会把过程提炼成技能；
- **自动改进**：已有技能在多轮使用中遇到更好的做法，Hermes 会更新它；
- **随时查看**：通过 `/skills` 命令查看和管理当前技能。

![自进化技能循环](/images/hermes/skills/01-skill-evolve.png)

### 1.3 开放标准：agentskills.io

技能使用 **SKILL.md 格式**，兼容 **agentskills.io 开放标准**。这意味着技能不绑定 Hermes 一家——同一份技能文件，理论上可以在其他支持该标准的 Agent 之间迁移复用。标准格式让"技能"成为可携带的资产，而不是锁在某个产品里的黑盒。

## 二、技能 vs 记忆：一个存"事实"，一个存"做法"

这是 Hermes 里最容易混淆的一对概念，核心区别一句话：

| 对比项 | 记忆（Memory） | 技能（Skill） |
| --- | --- | --- |
| 存什么 | 事实：偏好、项目信息、结论 | 步骤：怎么做、按什么流程 |
| 类型 | 陈述性记忆 | 程序性记忆 |
| 典型载体 | `MEMORY.md` / `USER.md` | `SKILL.md` |
| 回答的问题 | "是什么？" | "怎么做？" |
| 触发方式 | 对话中随时注入 | 遇到匹配任务时调用 |

举例：记忆里存"这个项目的发布流程是先测试再打 tag"——这是**事实**；技能里存"发布三步：跑测试 → 打 tag → 触发 CI"——这是**做法**。两者可以配合：技能告诉 Agent 按什么步骤走，记忆提供每一步需要的具体事实（服务器地址、仓库名）。

::: tip 何时该升级为技能
当发现"同类任务做完好几遍、每次都要重来"时，就是沉淀技能的信号——把流程告诉 Hermes："以后这类任务按这套流程做"，或让它自己提炼。
:::

## 三、技能的创建方式

### 3.1 自动创建 / 改进（主力方式）

这是 Hermes 的特色：完成任务后，Agent 自动判断哪些经验值得沉淀成技能。你只需要：

```text
以后遇到这种"批量重命名"的任务，按刚才那套流程来做。
```

或更省心——Hermes 会在完成复杂任务后**主动**建议并创建技能，无需你下指令。

### 3.2 手动编写 SKILL.md

掌握标准格式，你也能自己写技能（详见第四章）。编写后放入技能目录，Hermes 就能发现并使用它。

### 3.3 /skills 查看与管理

在 TUI 中输入 `/skills`，列出当前已沉淀的技能，查看技能是否生效、内容是否准确。也可以配合 `/memory` 对比：哪个是事实、哪个是流程。

::: warning 技能也需审核
自动生成的技能是"初稿"，不一定最优。定期用 `/skills` 检查：步骤是否过时、是否与你的项目实际相符、有没有冗余。技能是"越用越准"，前提是中间有人把关。
:::

## 四、技能结构：一份 SKILL.md 长什么样

标准 SKILL.md 通常包含三部分：**frontmatter（元信息）**、**正文步骤**、**scripts / references（脚本与参考）**。

| 部分 | 作用 | 内容示例 |
| --- | --- | --- |
| frontmatter | 定义技能的元信息 | 名称、描述（何时触发） |
| 正文 | 可执行的操作步骤 | 步骤清单、注意事项、检查点 |
| scripts | 辅助脚本 | 命令序列、工具调用脚本 |
| references | 参考材料 | 模板、示例、外部链接 |

### 4.1 可复制示例：发布技能

以"发布文档站点"为例：

```markdown
---
name: release-docs
description: 发布 VitePress 文档站的完整流程。当用户说"发布文档""发版""发布上线"时使用。
---

# 发布文档站点

## 步骤
1. 检查工作区：`git status` 确认无未提交改动；
2. 运行构建：`pnpm docs:build`，确认无报错；
3. 预览产物：`pnpm docs:preview`，抽查首页与导航；
4. 提交与打 tag：`git add -A && git commit -m "release: <版本号>"`，再 `git tag <版本号>`；
5. 推送到远端：`git push --tags`，触发 CI 部署；
6. 验证线上：访问预览 URL，确认页面正常。

## 注意事项
- 版本号遵循语义化版本（major.minor.patch）；
- 若构建报错，先修复再继续，不要跳过检查。

## 参考
- 部署配置：docs/deploy 说明
- 历史发布记录：docs/changelog
```

frontmatter 的 `description` 最关键——它决定**何时触发**该技能。写得越清楚（触发场景 + 触发指令），Agent 越能精准匹配。

## 五、技能市场与生态

技能是开放标准，意味着存在**跨 Agent 的技能市场**。以 **LobeHub** 等社区平台为代表的技能市场，提供大量现成技能（网页处理、文档生成、数据整理等），可以按需导入，避免从零编写。

| 生态位置 | 说明 | 用途 |
| --- | --- | --- |
| 本地技能目录 | `~/.hermes/skills/` 等 | 自产自用，最可控 |
| 社区技能市场 | LobeHub 等平台 | 导入现成技能，快速起步 |
| 开放标准 | agentskills.io | 技能跨 Agent 复用的格式底座 |

![技能市场](/images/hermes/skills/03-skills-market.png)

导入社区技能后，建议先跑通一两个任务再投入正式使用——**外来技能未经你环境验证，可能与你的工作流不完全匹配**。另外注意 Hermes 的**插件（Plugins）**与技能的边界：插件更偏向"安装的分发单元"，可以打包技能、工具、配置；技能是其中的核心内容单元。要分发一整套能力（技能 + 工具 + 配置），用插件；单论可复用的"做法"，就是技能。

::: warning 社区技能要审
导入技能前先读它的步骤、脚本，确认没有危险操作（删除、执行远端代码）。技能是可执行指令，来源不明的技能等于把控制权交给陌生人写的流程。
:::

## 六、实战案例：沉淀你的发布流程技能

### 6.1 场景一：让 Hermes 自己沉淀

先完整地做完一次任务，让 Hermes 记住这套流程：

```text
帮我把文档发布一遍：跑测试、构建、打 tag、推送、验证线上。以后类似的发布任务都按这个流程做。
```

Hermes 完成发布后，会把过程提炼成 `release-docs` 技能并自动保存。下次你只说一句"发布文档"，它就会照着技能走完整个流程。

### 6.2 场景二：手动编写自定义技能

如果流程高度定制（比如带特定审批、特定命名规则），手动写更精确——按第四章的 SKILL.md 模板写好放入技能目录即可。写好后再用 `/skills` 确认它已被加载。

### 6.3 场景三：技能用于定时任务

技能不只是对话里用，还能挂到 cron 定时任务上。官方提供 `--skill <name>` 参数，例如 `hermes cron create "every 2h" "check server status" --skill blogwatcher`——定时任务在独立的新会话中运行，技能保证它"知道怎么做"，结果稳定可复用。

## 七、最佳实践与常见问题

### 7.1 最佳实践

1. **技能要"小而专"**：一个技能解决一类任务，别做成"万能流程"，否则触发判断会模糊；
2. **description 写清楚**：触发场景和触发指令写具体，Agent 才能精准匹配；
3. **允许并推动自进化**：任务完成为了沉淀技能多说一句"按这套流程来"，长期收益巨大；
4. **定期清理**：技能也是会过时的资产，用 `/skills` 审视，删掉不再用的；
5. **注意与记忆分工**：流程进技能、事实进记忆，别把"怎么做"写进 MEMORY.md，也别把偏好写成技能。

### 7.2 常见问题排查

| 问题 | 排查步骤 |
| --- | --- |
| 技能不触发 | ① 用 `/skills` 确认技能存在且已加载；② 检查 `description` 是否覆盖了你的表述；③ 触发关键词尽量用技能描述中的原词 |
| 技能内容过时 | ① 手动编辑 SKILL.md 更新步骤；② 让 Hermes 用新流程重跑一次，它会更 新技能；③ 用 `/skills` 确认更新已生效 |
| 技能冲突（多个技能匹配同一任务） | ① 审视各技能 description，缩小重叠范围；② 把更通用的技能改得更专；③ 明确哪份技能"最终为准" |
| 技能太多、相互干扰 | ① 归档或删除低频技能；② 合并高度相似技能；③ 保持"小而专"，从源头控制数量 |
| 导入的社区技能行为异常 | ① 先审读技能步骤与脚本；② 在本机小范围试跑；③ 不行就删除，改为自己编写 |

## 总结

自进化技能是 Hermes "和你一起成长"的**最独特引擎**：以 `SKILL.md`（frontmatter + 步骤 + scripts/references）为载体、兼容 agentskills.io 开放标准，让 Agent 能自动创建、改进、复用"怎么做"的程序性记忆。它与记忆的分工清晰——**记忆存事实、技能存做法**。用好它：让 Hermes 多沉淀、自己会写 SKILL.md、从技能市场有选择地导入、定期用 `/skills` 把关。掌握本章，你的 Hermes 就不再是"每次都从零开始"的工具，而是经验越攒越厚、越用越顺手的长期协作者。
