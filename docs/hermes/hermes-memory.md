# Hermes 记忆使用教程

> 来源：[Hermes Agent 官方文档](https://hermes-agent.nousresearch.com/docs/zh-Hans/) · [GitHub: NousResearch/hermes-agent](https://github.com/NousResearch/hermes-agent)

用普通聊天机器人的痛点是：上一句刚说过的话，换个会话就全忘了。你反复叮嘱的偏好、反复交代的规则，每次都要重讲一遍。而 Hermes Agent 的口号是 **"The agent that grows with you"（和你一起成长的 Agent）**——支撑"成长"的，正是它的**持久记忆**。记忆让 Hermes 跨会话记住你是谁、你偏好的风格、你项目的关键事实，并且越用越懂你。本章从核心概念讲到实战，帮你把"过目就忘的工具"变成"记得住你的伙伴"。

## 一、记忆系统核心概念

### 1.1 什么是持久记忆（一句话懂）

**持久记忆**是 Hermes 跨会话持续增长、长期保存的事实信息，默认存放在 `~/.hermes/memories/` 目录。它让 Agent 在每次新会话开始时都能回忆起过去积累的知识——你告诉过它的事情，它下次见面还记得。

类比理解：会话历史像**草稿纸**，用完就丢；持久记忆像**笔记本**，重要的事写下来，随时翻查。Agent 每次对话都会"翻一翻"这本笔记本，所以你说过一次的事情，它不需要你重复第二遍。

### 1.2 记忆 vs 上下文 vs 技能：三者分工

很多人分不清"记忆""上下文""技能"三个概念，先记住一句话：**记忆存事实，上下文是当次思考的空间，技能存做法**。

| 概念 | 存储什么 | 生命周期 | 典型载体 | 一句话理解 |
| --- | --- | --- | --- | --- |
| 记忆（Memory） | 事实：用户偏好、项目事实、关键结论 | 跨会话长期存在 | `~/.hermes/memories/MEMORY.md`、`USER.md` | "你是谁、你的项目长什么样" |
| 上下文（Context） | 当次对话的全部输入（系统提示、SOUL、会话历史） | 单次会话 | system prompt、`SOUL.md`、上下文文件、对话历史 | "此刻它思考时眼前摊开的材料" |
| 技能（Skills） | 可复用的操作步骤（程序性记忆） | 跨会话长期存在 | `SKILL.md` | "遇到这类事该怎么做" |

在 Hermes 中，**技能本质上是"程序性记忆"**——记忆体系里再细分一层：陈述性记忆记事实（"用户的数据库是 PostgreSQL"），程序性记忆记流程（"部署流程是：先测试再打 tag 再发布"）。二者的区别和协作，会在《代理技能使用教程》里展开。

![持久记忆系统](/images/hermes/memory/01-memory-system.png)

### 1.3 核心价值

- **免去重复沟通**：一次讲清楚偏好，之后每次对话自动生效；
- **项目知识沉淀**：关键事实（技术栈、目录结构、约定）写进记忆，Agent 不再反复追问；
- **随使用增长**：用越久，记忆越完整，Agent 越"懂你"，这正是"和你一起成长"的字面含义。

## 二、记忆存储在哪里

Hermes 零遥测，所有数据都保存在本机。默认存储位置：

| 平台 | 记忆目录 |
| --- | --- |
| Linux / macOS / WSL2 | `~/.hermes/memories/` |
| 原生 Windows | `%LOCALAPPDATA%\hermes\memories\` |

记忆目录下主要是两个 Markdown 文件，各有**字符上限**：

| 文件 | 用途 | 字符上限 |
| --- | --- | --- |
| `MEMORY.md` | 关于 Agent 自身、任务、项目、环境的记忆 | 2200 字符 |
| `USER.md` | 关于用户个人的记忆（偏好、背景、习惯） | 1375 字符 |

::: warning 字符上限会强制截断
`MEMORY.md` 上限 **2200 字符**、`USER.md` 上限 **1375 字符**，超出部分会被截断丢弃。记忆要精炼到"要点式"，别把整篇文章塞进去——塞得越多，被截断的风险越大，而且越长越稀释重要信息。
:::

## 三、memory 工具：增删改查

Hermes 内置 `memory` 工具集，负责对持久记忆进行**写入、替换、删除**三类操作。注意它是 Agent 调用的**工具**，不是你要背的 CLI 命令——你的工作是"告诉 Hermes 记住什么"，具体怎么写由它自己完成。

| 操作 | 作用 | 典型触发场景 |
| --- | --- | --- |
| add | 新增一条记忆 | "记住：我偏好 PostgreSQL，别用 MySQL" |
| replace | 替换已有记忆 | 偏好变化："改成：从今天起用 DuckDB" |
| remove | 删除不再需要的记忆 | "忘掉我之前说的那个旧服务器地址" |

每次写入都会经过**安全扫描**，避免敏感或危险内容被无脑写进长期记忆。

### 3.1 让 Agent 记住一件事

在对话里直接用自然语言下达记忆指令即可：

```text
记住：这个项目的后端是 FastAPI，数据库是 PostgreSQL，本地启动命令是 docker compose up -d。
```

Hermes 会调用 `memory` 工具的 add 操作，把事实整理进记忆文件。以后任何新会话，它都能直接答出你的项目情况，不用你重新介绍。

### 3.2 修正与删除

```text
# 修正（replace）：启动命令改了
更新记忆：启动命令改成 uv run uvicorn app.main:app --reload

# 删除（remove）：服务器地址不用了
忘掉之前的旧服务器地址。
```

### 3.3 用 /memory 查看

在 TUI 中输入斜杠命令 `/memory`，可直接查看当前记忆内容，确认 Agent"记住了什么"。这样你能及时核对：记忆是否完整、有没有被截断、要不要清理过时条目。

::: tip 怎么触发才高效
- 一次性讲清楚：不要分好几条挤牙膏，把相关事实在一句话里讲完，Agent 会整理成结构化条目；
- 记忆是"长期设置"：适合放稳定的偏好与事实，临时任务信息交给会话历史就够了，别污染长期记忆。
:::

## 四、可插拔记忆提供商

Hermes 的本地文件记忆是默认方案，但它支持**可插拔的记忆提供商**，把记忆能力托管给外部服务。官方提及的提供商包括 **Honcho、Mem0、Holographic** 等。

| 提供商 | 定位 | 特点 |
| --- | --- | --- |
| Honcho | 面向 Agent 的智能记忆后端 | 为用户/Agent 构建结构化、可检索的长期记忆 |
| Mem0 | 记忆层（Memory Layer） | 帮 AI 应用管理用户画像与偏好，跨会话复用 |
| Holographic | 记忆/人格管理系统 | 强调为 Agent 提供统一的人格与记忆服务 |

选择思路：**本地记忆**适合个人使用、数据敏感场景（数据不出本机，零遥测）；**外部提供商**适合团队共享记忆、需要记忆在不同设备/Agent 间同步的复杂场景。具体配置方式（接入地址、API Key、字段）不同版本有差异，以官方文档为准。

::: warning 数据在哪里？
选择外部记忆提供商时，意味着长期记忆会离开本机。如果你的记忆里含敏感信息（密钥、内部架构），默认本地存储更稳妥；切到外部提供商前先评估数据合规。
:::

## 五、实战案例

### 5.1 场景一：记住用户偏好

每次写代码风格都不同？一次性告诉 Hermes：

```text
记住：我喜欢简洁的代码注释，中文回复，函数命名用 snake_case，代码块要带语言标记。
```

之后无论开多少新会话，Hermes 都会遵循这套偏好，写出来的代码、回复的风格稳定一致，不需要你反复提醒。

### 5.2 场景二：沉淀项目知识

换项目重开会话，最烦的就是重新讲一遍背景。用记忆一次讲透：

```text
记住项目信息：这是一个 VitePress 文档站，放在 docs/ 下，采用"一、二、三"中文章节编号，
命令示例要可复制，配置项必须与实际工具一致，图片放在 docs/public/images/ 下。
```

新会话直接问"我们的文档规范是什么？"，Hermes 立刻答得上来。这些项目事实会长期沉淀，成为你和 Agent 之间共享的"项目常识"。

## 六、自动写入与手动管理

### 6.1 自动写入

Hermes 会在对话过程中**自动判断并写入记忆**——当你明确说"记住……"、或反复提供关键事实时，它会主动调用 memory 工具沉淀。这也是"自进化闭环"的一部分：不仅技能会自动成长，记忆也会自动积累。

### 6.2 手动管理

自动写入是便利，但也可能写进你不想长期保存的东西。建议定期手动打理：

- 用 `/memory` 查看当前全部记忆；
- 对过时、错误的信息，明确要求 replace 或 remove；
- 保持文件在字符上限内，留出增长空间，避免重要新记忆被截断。

::: tip 记忆是双刃剑
自动写入省心，但**错误记忆比没记忆更糟**——它会在每次对话中悄悄误导 Agent。发现记忆有误，第一时间用 replace 修正，别等到被误导了才想起清理。
:::

## 七、最佳实践与常见问题

### 7.1 最佳实践清单

1. **只存长期事实**：偏好、项目约定、稳定环境信息，才值得进记忆；
2. **精简优先**：记忆是"要点笔记"，不是完整文档，控制在上限以内；
3. **定期核对**：每周用 `/memory` 扫一遍，清理过时条目；
4. **敏感信息保守**：默认本地存储，切换外部提供商前评估数据合规；
5. **讲清"记住/更新/忘掉"**：用明确指令驱动 add/replace/remove，别让 Agent 猜。

### 7.2 常见问题排查

| 问题 | 排查步骤 |
| --- | --- |
| 记忆被截断 / 丢失 | ① 用 `/memory` 查看是否超字符上限；② 超限则精简内容，删掉旧条目腾出空间；③ 确认在正确的平台目录（Windows 是 `%LOCALAPPDATA%`） |
| 记忆冲突（新旧矛盾） | ① 用 replace 显式替换旧条目；② 明确优先级："以最新为准"；③ 避免同名事实分散在多条里 |
| 明明说过却想不起来 | ① 确认当时是否真的写入了（`/memory` 查看）；② 可能超限被截断，精简后重写；③ 检查是否用的临时会话、未触发记忆写入 |
| 不想让它记住某些事 | 明确说"不要记住这条"；已写入的用 remove 删除 |

## 总结

持久记忆是 Hermes "和你一起成长"的核心引擎：它把跨会话的**事实**沉淀到 `~/.hermes/memories/`，用 `memory` 工具（add / replace / remove）配合安全扫描完成读写，并支持 Honcho、Mem0、Holographic 等可插拔提供商。用好记忆的关键是**精炼、定期打理、只存长期事实**，并记住两个硬上限（`MEMORY.md` 2200 字符、`USER.md` 1375 字符）。掌握本章，你的 Hermes 将第一次真正"记得你"——这比任何一次性工具都更接近一个长期协作者。下一章我们聊 Agent 的"工作台"——上下文。
